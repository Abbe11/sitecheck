Web Vuln Lab

Same attack. One switch. Breach or blocked.

The three web bugs behind most breaches - SQL injection, XSS, and broken access control - shown live. Flip the switch and run the same attack against vulnerable code, then against the fixed version. Everything is simulated in your browser; nothing real is attacked.

VULNERABLECode is written the naive, insecure way
Attack 01 / SQL Injection

Login bypass


    

    
Fix: parameterized queries - send the input as data on a separate channel, never glued into the SQL string.

  

  

    Attack 02 / Cross-Site Scripting
    
Malicious comment

    
    
    

    

    
Fix: output encoding - render user input as text, so a script tag shows as characters, never runs. A Content-Security-Policy is the backstop.

  

  

    Attack 03 / Broken Access Control (IDOR)
    
Read someone else's invoice

    
You are logged in as user #1001. The app fetches invoices by ID. Try changing it to 1002 - a stranger's invoice.

    
    
    

    

    
Fix: on every request, check the record belongs to the logged-in user before returning it. Never trust an ID from the client.
